# Requirements: Milestone 21.0

## Epic
**Expansão do Painel Administrativo, Sessão Isolada, Mensageria & Expurgo Automático**
Isolar a autenticação administrativa com sessão/cookie próprios (`admin_session`), consolidar o sistema de logs e auditoria em schema único, criar gestão completa de vagas expostas com expurgo automático agendado (retenção de 3 semanas em lotes para VPS), expandir o admin com módulos de Usuários, Pagamentos e Mensageria (Telegram + WhatsApp).

## User Stories
1. Como administrador do sistema, quero ter uma sessão isolada (`admin_session`) com rota de login própria (`/admin/login`), para garantir que permissões administrativas sejam totalmente segregadas dos usuários comuns e protegidas contra escalonamento de privilégios.
2. Como administrador, quero visualizar logs unificados (sistema, ações administrativas e mensageria) com suporte a filtros e busca rápida, para auditar operações e investigar falhas com facilidade.
3. Como administrador de uma plataforma rodando em VPS limitada, quero gerenciar as vagas expostas no site e ter um expurgo automático diário em lotes para vagas antigas (> 21 dias), para manter a base de dados leve e com performance sem travar as tabelas.
4. Como administrador, quero gerenciar contas de usuários, alterar planos, suspender contas e ter visão financeira de pagamentos e assinaturas em telas dedicadas no painel.
5. Como administrador, quero acompanhar o status e o log de envio de notificações via Telegram e WhatsApp, com capacidade de reenviar notificações que falharam.

## Requirements

### Phase 76: Autenticação Admin Isolada & Sessão Dedicada (`admin_session`)
- [ ] `REQ-01`: Implementar sistema de sessão isolada para o admin via cookie `admin_session` com chave de assinatura/JWT separada da sessão de usuário comum.
- [ ] `REQ-02`: Criar rota `/admin/login` com formulário seguro, expiração de sessão curta (2 horas) e middleware de proteção `requireAdminSession` para todas as rotas `/admin/**` e `/api/admin/**`.
- [ ] `REQ-03`: Implementar registro auditável de tentativas de login no admin (sucesso e falha) armazenando IP e User-Agent.
- [ ] `REQ-04`: Criar suíte de testes `src/test-phase76.ts` validando o isolamento de sessão, bloqueio de acessos não autorizados e expiração do cookie `admin_session`.

### Phase 77: Unificação de Logs & Auditoria Admin (`/admin/logs`)
- [ ] `REQ-05`: Criar schema unificado de logs no SQLite (`logs` com `tipo`: `sistema` | `acao` | `mensageria`, `nivel`, `origem`, `mensagem`, `metadata` JSON, `created_at` com índice em `(tipo, created_at)`).
- [ ] `REQ-06`: Desenvolver API REST `/api/admin/logs` e interface web `/admin/logs` com paginação, busca por texto, filtro por tipo/nível/origem e inspeção de metadata JSON.
- [ ] `REQ-07`: Integrar o registro automático de ações administrativas (login, alteração de plano, exclusão manual de vaga, disparo de expurgo).
- [ ] `REQ-08`: Criar suíte de testes `src/test-phase77.ts` validando a gravação, filtragem e recuperação paginada de logs unificados.

### Phase 78: Gestão de Vagas Expostas & Job de Expurgo Automático (`/admin/vagas`)
- [ ] `REQ-09`: Construir módulo `/admin/vagas` com paginação, filtros por status (aprovada, pendente, descartada, expirada), edição manual de campos e ações de soft-hide e exclusão definitiva.
- [ ] `REQ-10`: Criar serviço/job de expurgo automático diário para vagas com mais de 21 dias sem candidaturas ativas vinculadas, executando a exclusão em lotes de 500 registros (`DELETE ... LIMIT 500`) com retenção configurável em banco.
- [ ] `REQ-11`: Registrar estatísticas de cada ciclo de expurgo no log unificado (`tipo: sistema`, `origem: cron:expurgo-vagas`) e disponibilizar botão de acionamento manual no painel.
- [ ] `REQ-12`: Criar suíte de testes `src/test-phase78.ts` validando as regras de exclusão por idade, preservação de vagas com candidatura ativa e execução do expurgo em lotes.

### Phase 79: Gestão de Usuários, Permissões & Suporte (`/admin/usuarios`)
- [ ] `REQ-13`: Desenvolver módulo `/admin/usuarios` com busca, filtros por plano e status, e tabela paginada com visão completa do usuário.
- [ ] `REQ-14`: Criar painel de detalhes do usuário exibindo dados cadastrais, plano ativo, histórico de candidaturas e transações financeiras.
- [ ] `REQ-15`: Implementar ações de gestão de conta: suspensão/reativação, ajuste manual de plano, solicitação de reset de senha e funcionalidade de impersonate com registro auditável em log.
- [ ] `REQ-16`: Criar suíte de testes `src/test-phase79.ts` validando os fluxos de alteração de estado do usuário e auditoria de ações.

### Phase 80: Gestão Financeira & Pagamentos (`/admin/pagamentos`)
- [ ] `REQ-17`: Construir dashboard financeiro em `/admin/pagamentos` exibindo métricas de MRR, novos pagamentos, churn de assinaturas e taxa de inadimplência.
- [ ] `REQ-18`: Desenvolver listagem de transações com filtros por gateway, status e plano, além de log de webhooks de pagamento recebidos para debug.
- [ ] `REQ-19`: Criar suíte de testes `src/test-phase80.ts` para validação de endpoints financeiros e agregação de métricas.

### Phase 81: Hub de Mensageria: Telegram & Estrutura WhatsApp (`/admin/mensageria`)
- [ ] `REQ-20`: Implementar sub-aba Telegram no módulo `/admin/mensageria` exibindo status da integração, fila de envio, histórico de mensagens enviadas e botão de reenvio manual.
- [ ] `REQ-21`: Estruturar a sub-aba WhatsApp e o schema unificado de envios com a coluna `canal` (`telegram` | `whatsapp`), prevendo integração com Meta Cloud API / Baileys e logs de entrega.
- [ ] `REQ-22`: Criar suíte de testes `src/test-phase81.ts` cobrindo o registro e controle da fila de mensageria.
