# Requirements: Milestone 20.0

## Epic
**Resiliência Geográfica, Tratamento de Localizações Omissas & Tolerância de Payloads**
Eliminar falsos-positivos de Hard Block geográfico em vagas presenciais/híbridas que trazem a cidade correta mas omitem a UF no anúncio, garantir pontuação neutra para vagas presenciais sem localização informada, e flexibilizar a validação Zod da API de perfil do candidato para tolerar strings vazias e sanitizar entradas textuais de ponta a ponta.

## User Stories
1. [x] Como candidato que busca vagas presenciais ou híbridas, quero que oportunidades anunciadas apenas com o nome da minha cidade (ex: "Florianópolis", "Curitiba", "São Paulo", sem sigla de estado) sejam reconhecidas como match de mesma cidade (score 100), sem sofrer Hard Block indevido.
2. [x] Como candidato, quero que vagas presenciais onde o anunciante omitiu a localização (campo vazio ou nulo) não me bloqueiem com Hard Block de 35%, sendo tratadas com pontuação neutra (score 70) sem restrição geográfica impeditiva.
3. [x] Como desenvolvedor ou cliente da API REST, quero poder enviar payloads com campos opcionais vazios (ex: `state: ""`) sem receber erro 400 de validação, com o sistema normalizando automaticamente para `null`.

## Requirements

### Phase 74: Refinamento de Matching Geográfico (Cidades sem UF & Localizações Omissas)
- [x] `REQ-01`: Refatorar `evaluateGeographicCompatibility()` em `candidateMatcher.ts` para tratar vagas presenciais/híbridas com campo `location` nulo, vazio ou sem dados geográficos, retornando avaliação neutra (`locationScore: 70`, `locationCap: 100`, `isGeoHardBlocked: false`).
- [x] `REQ-02`: Permitir match municipal (`locationScore: 100`, sem teto) quando a cidade do candidato constar como palavra inteira na localização da vaga mesmo que a vaga omita a UF, desde que não haja menção explícita a outro estado brasileiro conflitante e prevenindo colisões de prefixo (ex: "Rio" vs "Rio Grande do Sul").
- [x] `REQ-03`: Criar suíte de testes `src/test-phase74.ts` validando vagas com cidades sem UF ("Florianópolis", "Curitiba", "São Paulo"), vagas sem localização informada e regressões contra colisões semânticas.

### Phase 75: Resiliência de Payload e Sanitização na API de Perfil
- [x] `REQ-04`: Atualizar `profileSchema` em `src/app/api/candidate/profile/route.ts` para aceitar `state: ""` (string vazia) convertendo automaticamente para `null`, mantendo a validação estrita das 27 UFs válidas.
- [x] `REQ-05`: Adicionar sanitização padronizada de espaços (`.trim()`) e conversão para `null` nos demais campos textuais opcionais (`target_role`, `seniority`, `expected_salary`, `bio`) para consistência total da base de dados.
- [x] `REQ-06`: Criar suíte de testes `src/test-phase75.ts` validando a aceitação e normalização de payloads com campos vazios e espaços na API de perfil.
