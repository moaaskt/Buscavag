# Requirements: Milestone 18.0

## Epic
**Ingestão Agnóstica Multi-Tenant, Dinamização de Abordagens e Blindagem do Sistema**
Alinhar a ingestão do BuscaVag com o ecossistema multi-tenant da plataforma, transformando o HermesEvaluator em um parser técnico neutro de oportunidades de TI, ajustando as barreiras de descarte na borda para não eliminar vagas de outros perfis e perfis seniores, dinamizando o pitch de abordagem de acordo com o perfil do usuário logado e blindando a segurança e suíte de testes.

## User Stories
1. [x] Como candidato de qualquer nível (Estágio, Júnior, Pleno, Sênior) ou stack, quero que o banco de dados armazene as vagas técnicas coletadas para que meu feed de recomendadas encontre oportunidades aderentes ao meu perfil.
2. [x] Como sistema, quero que o avaliador de vagas extraia metadados técnicos objetivos (cargo, senioridade requerida, stacks, modalidade e faixa salarial) sem enviesar a classificação para um candidato específico.
3. [x] Como sistema, quero descartar na ingestão apenas vagas não-tech, operacionais ou categorizadas como fora de tecnologia, preservando a higienização do banco de dados.
4. [x] Como candidato, quero que o botão "Copiar Pitch" no modal da vaga gere uma mensagem personalizada com minhas stacks primárias e meu cargo pretendido, em vez de um texto genérico fixo.
5. [x] Como administrador do sistema, quero ter certeza de que em ambiente de produção o sistema não suba com uma chave de autenticação JWT padrão pública.
6. [x] Como desenvolvedor, quero rodar `npm test` e ter toda a suíte de regressão executada de ponta a ponta em um único comando.

## Requirements

### Phase 68: Parser Técnico Agnóstico no HermesEvaluator & Ingestão Multi-Tenant
- [x] `REQ-01`: Refatorar prompt e lógica do `HermesEvaluator` para extração objetiva de metadados de vagas (cargo, nível de senioridade, stack de tecnologias, modelo de trabalho e salário) de forma agnóstica a candidatos específicos.
- [x] `REQ-02`: Adaptar a barreira eliminatória em `src/index.ts` para descartar na ingestão apenas vagas classificadas como não-tech ou fora de TI (`category === 'Other'` ou sem correspondência técnica), permitindo a coexistência de vagas de múltiplos níveis e tecnologias.
- [x] `REQ-03`: Ajustar regras de notificações via Telegram para manter filtro configurável por variáveis de ambiente para o canal de alerta.

### Phase 69: Dinamização do Pitch de Abordagem & Experiência do Candidato
- [x] `REQ-04`: Dinamizar a geração de pitch no `JobModal.tsx` utilizando as stacks primárias (`primary_stack`) e cargo pretendido (`target_role`) do perfil do candidato logado.
- [x] `REQ-05`: Manter suporte a abordagens específicas para vagas originadas de posts informais (LinkedIn Posts / Facebook Groups) e contato direto (`directContact`).
- [x] `REQ-06`: Garantir fallback elegante caso o perfil do candidato ainda não possua stacks primárias cadastradas, com garantia estrita anti-alucinação.

### Phase 70: Blindagem de Segurança, Runner Unificado de Testes & Resiliência
- [x] `REQ-07`: Adicionar validação estrita no `src/lib/auth.ts` para bloquear inicialização em `NODE_ENV=production` se `AUTH_SECRET` for ausente, default hardcoded ou menor que 32 caracteres.
- [x] `REQ-08`: Criar runner de testes unificado (`npm test`) no `package.json` integrando 9 suítes determinísticas automatizadas do projeto com relatório tabular.
- [x] `REQ-09`: Adicionar lock in-flight com liberação em `finally` e cooldown de 5s contra reprocessamento concorrente de currículo em `/api/candidate/analyze-cv`.
